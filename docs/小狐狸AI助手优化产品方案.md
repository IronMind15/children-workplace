# 小狐狸 AI 助手优化 · 产品方案（可落地版）

> 版本：v0.1（产品方案稿，未改代码）
> 范围：小狐狸 AI 助手的「界面与交互」+「隐藏玩法机制」两大块
> 原则：先方案后实施；方案经确认后再进入开发

---

## 一、背景与目标

当前小狐狸 AI 助手已具备：聊天（推荐问题/自由提问/语音）、分岛费曼小课堂、提问得火花、火花解锁 3 只神秘小怪、精灵成长/觉醒、错题本综合解析等能力。但存在以下体验问题：

1. 「聊天」与「费曼小课堂」两个 Tab 职责混杂——「岛上小课堂」卡片出现在聊天 Tab 里，费曼 Tab 又只有费曼学习法，结构不清晰；
2. 回复区域滚动/字体对儿童不够友好（回答字号偏小、非嵌入式场景聊天区有高度上限但操作区易被遮挡）；
3. 隐藏小怪仅 3 只、靠火花门槛随机现身，随机性过强、没有保底，孩子可能失去期待；
4. 隐藏小怪的问题多为「非知识点」（谜语/生活认知），却仍然走完整「选精灵 → 答题」战斗流程，容易让孩子困惑（选了精灵但题跟本领无关）；
5. 隐藏小怪没有独立的稀有度、形象、图鉴与彩蛋，收集感弱（图鉴目前用随机小怪图像）。

**本次目标**：
- 界面更清爽、字体更大、可滚动、好点按；
- 隐藏玩法更有「期待感」：火花挂钩、种类扩充、稀有度、保底机制、收集图鉴、彩蛋故事；
- 严格遵循约束：**凡与知识点无关的隐藏小怪，绝不再引导孩子「选精灵」**。

## 三、界面与交互优化

### 3.1 Tab 重构（聊天 / 费曼小课堂）

```
┌─────────────────────────────────────────────┐
│  [💬 聊天]  [📚 费曼小课堂]        🔑连接AI │   ← 分段切换，图标加大
├─────────────────────────────────────────────┤
│  聊天 Tab：                                │
│    · 狐狸头像 + 对话气泡（可滚动）          │
│    · 「好奇小问号」推送条（见 3.2）         │
│    · 快捷问题 chips + 自由输入 + 语音       │
├─────────────────────────────────────────────┤
│  费曼小课堂 Tab（合并 岛上小课堂 + 费曼）： │
│    · 顶部：🏝️ 岛上小课堂卡（岛域/分层/引导）│
│    · 中部：选题 chips（默认当前岛）          │
│    · 主体：当小老师对话区（可滚动，字号大）  │
└─────────────────────────────────────────────┘
```

- **聊天 Tab = 纯对话**：把现在的「岛上小课堂」卡片整体移出聊天 Tab，聊天区只保留对话 + 提问入口 + 「好奇小问号」推送条。聊天窗口全屏可用高度、可滚动，回复永不遮挡输入框。
- **费曼小课堂 Tab = 岛上小课堂 + 费曼学习法二合一**：
  - 上方放「岛上小课堂」卡（复用现 `tierGuidance`/`tierBadge`/`islandQuestions` 逻辑，字体放大）；
  - 下方是费曼学习法（`FeynmanChat` 改造版：字号 `text-base`、对话框 `max-h` 提高并 `flex-1` 自适应滚动、输入区固定在底部）；
  - 狐狸形象与聊天 Tab 一致：统一用 🦊 头像（聊天区已有），费曼对话里的 AI 气泡前缀 🦊 保持一致，去掉不统一的图标样式。
- 切换动画：Tab 切换时内容淡入，儿童能感知「换了页面」。

### 3.2 聊天 Tab ·「好奇小问号」——定期推送可点按小问题

**目的**：让孩子持续想和 AI 互动，且「有东西可点、点完有回应」，降低空白期。

**机制**：
1. 问题来源池（三合一）：
   - 理解 AI：`AI_TIPS`（如「AI 说的话全是真的吗？」）＋ 新增「AI 朋友是什么/怎么分辨真假」类问题；
   - 理解学习：费曼提问、元认知相关生活化问题（如「为什么要检查答案？」）；
   - 生活认知：谜语、趣味数学、百科小知识（非知识点，纯兴趣）。
2. 推送节奏（防打扰）：
   - 进入聊天 Tab 时推 1 条；
   - 之后每完成 2 次提问（或空闲 20 秒未互动）推送 1 条新问题；
   - 问题卡片 = 狐狸气泡 + 2~3 个快捷答案 chips，**一点即问**（走现有 `askQuestion`，照样得火花）。
3. 展示形式：固定在对话区顶部的一条「🎲 好奇小问号」卡，点「换一个」刷新；已答过的问题当天不重复。

### 3.3 回复滚动与字体

| 位置 | 现状 | 目标 |
|---|---|---|
| 聊天回答 | `text-[15px]`，embedded 可滚 | `text-[17px]`，**始终可滚动**（非 embedded 也改为 `max-h` + 滚，输入框固定不被盖） |
| 聊天气泡 | — | 加「气泡内滚动」兜底：超长回复限高 40vh 内滚 |
| 费曼对话 | `text-sm`，`max-h-80` | `text-[16px]`，`flex-1` 自适应 + 底部输入固定 |
| 岛上小课堂卡 | `text-xs` | `text-sm`，标题 `text-base` |
| 快捷问题 chips | `text-[11px]` | `text-sm`，加大 padding（点按目标 ≥44px） |

## 四、隐藏玩法机制

### 4.1 火花 ↔ 隐藏小怪（强化现有挂钩）

现状：提问 +1 火花；火花达到门槛后该小怪在对应岛现身（可反复打，无收集概念）。

强化设计：
1. **明确「火花 = 召唤货币」的心智**：
   - 小狐狸对话区顶部常驻火花进度条：`✨ 12 / 20 · 再问 8 次就能遇到「传说·xx小怪」啦！`；
   - 达到门槛时狐狸主动播报：`✨ 火花满啦！快去岛上找神秘小怪吧！`（复用 `partner-message` 推送到对话区，并自动展开）。
2. **双通道现身**：
   - 通道 A（门槛现身）：`sparks.total >= required_sparks` 时小怪出现在对应岛（保留现有逻辑）；
   - 通道 B（保底邂逅，见 4.3）：聊够次数必出，与火花无关。

### 4.2 隐藏小怪扩充 + 稀有度

**目标池：10 只**（新增 7 只），分 3 档稀有度：

| 稀有度 | 数量 | 特点 | 火花门槛 | 示例 |
|---|---|---|---|---|
| 普通 | 4 | 常见，问题简单 | 3 / 6 / 9 / 12 | 为什么小怪、谜语小怪、星星小怪、时间小怪 |
| 稀有 | 4 | 带彩色特效，问题有趣 | 15 / 20 / 26 / 33 | 彩虹小怪、回声小怪、泡泡小怪、夜光小怪 |
| 传说 | 2 | 金色粒子特效，专属彩蛋故事 | 42 / 50 | 创世小怪、梦蝶小怪 |

每只小怪配置字段（落库）：
```
id / name / rarity(普通|稀有|传说) / art(专属立绘) / question / options
spark_cost / story(彩蛋故事，捕捉后解锁) / spawn_island / hint
```

**保底机制（核心）**：
- 全局「邂逅计数器」`pityCount`（记在 explorer 或 config，按用户维度）：
  - 每向 AI 提问 1 次 +1；每触发 1 次「保底邂逅」归零；
  - `pityCount >= 5` 时，**下一次提问后必定触发一次邂逅**（随机从未收集的隐藏小怪中优先抽取；已集齐则随机给一只 + 火花奖励），狐狸气泡播报 `🌟 奇迹降临！神秘小怪出现了！`，岛上出现该小怪（带 3 分钟存在期提示）。
- 效果：即使火花攒得慢，每 5 次聊天必有一次「惊喜」，保持期待感，避免随机性过强。
- 与火花门槛互不冲突：保底是「额外」邂逅，门槛是「常驻」现身。

### 4.3 吸引力设计

1. **稀有度视觉**：
   - 岛图上：普通 = 现有样式；稀有 = 彩色呼吸光晕；传说 = 金色粒子 + 慢速漂浮 + 星星拖尾；
   - 邂逅动画：出现时全屏「✨ 神秘小怪出现」淡入（1.5s），狐狸同时口播。
2. **专属形象**：为 10 只小怪各配一张专属立绘（替换目前图鉴里的随机小怪图）；无新美术前先用「emoji 大图标 + 专属配色底板」过渡。
3. **收集图鉴（神秘图鉴）**：
   - 新增「🔮 神秘图鉴」页签（挂在 `/spirits` 页顶部或新增 `/mystery`）：
     - 10 格收集格，未收集显示剪影 `❓`；
     - 已收集：立绘 + 名字 + 稀有度徽章 + 彩蛋故事（点开阅读）+ 捕捉日期；
     - 顶部进度：`已收集 3/10`，集齐某稀有度档有成就横幅。
4. **彩蛋故事**：每只传说/稀有小怪附 60~120 字小故事（捕捉后解锁，出现在图鉴与捕捉结算页），内容融入学习/好奇主题（如梦蝶小怪的故事讲「为什么同一个问题能有好几种解法」）。

### 4.4 关键约束：非知识小怪绝不引导「选精灵」

**问题现状**：隐藏小怪带 `correct_meta`，走 `intro → pick（选精灵）→ solve` 完整战斗，但题目却是谜语/生活认知，孩子会困惑「为什么答谜语还要先选加法精灵」。

**方案（战斗流程改造）**：
1. 新增战斗模式 `mode: "fun"`（仅隐藏小怪使用）：
   - **跳过精灵选择**：`phase` 从 `intro` 直接进 `solve`（不渲染 pickOptions/helperOptions）；
   - 题目为「单题闯关」或 2~3 道小问答，答对即胜利；
   - 胜利奖励 = 火花 + 隐藏小怪收集（写入新表 `mystery_catch`）+ 彩蛋故事解锁；**不调 trainWin / 不写精灵熟练度 / 不写错题本**（避免污染知识数据）；
   - 答错：狐狸给提示 + 重试，不扣血惩罚，儿童友好。
2. 数据层：隐藏小怪 `correct_meta` 置空（保留 `island` 用于出现位置）；`BattleFlow` 增加 `mode==="fun"` 分支；`page.tsx` 生成 `battleData.mode = "fun"`。
3. 兜底校验：任何 `mode==="fun"` 的战斗若误带 `correct_meta`，前端直接忽略选精灵步骤（双保险）。

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0（界面） | Tab 重构、字体/滚动改造、好奇小问号 | 聊天/费曼分区清晰，长回复可滚不挡输入，字号达标 |

## 七、验收标准与风险

### 验收标准
1. 聊天 Tab 无知识卡片混杂；费曼 Tab 含岛上小课堂且字体 ≥16px、可滚动；
2. 任意长度的回复都能滚动查看且不遮挡输入框；
3. 连续 5 次提问必触发一次隐藏小怪邂逅（新用户从 0 计数验证）；
4. 隐藏小怪战斗全程无「选精灵」界面；胜利后进入神秘图鉴、不污染熟练度/错题本；
5. 神秘图鉴 10 格、稀有度徽章、彩蛋故事均可正常展示。

### 风险与对策
| 风险 | 对策 |
|---|---|
| 保底机制被刷（反复提问刷邂逅） | 每日邂逅上限（默认 3 次）+ 邂逅存在期提示（3 分钟内出现） |
| 隐藏小怪题目与知识点混用 | 严格执行 `mode="fun"` + `correct_meta=null` 双保险，代码评审把关 |
| 美术资源不足 | 先用 emoji + 配色底过渡，专属立绘后补；不阻塞功能上线 |
| 图鉴/收集数据兼容旧库 | `mystery_catch` 新表 + 老用户默认 `pityCount=0`，无需迁移 |
