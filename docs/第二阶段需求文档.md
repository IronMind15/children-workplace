## 0. 为什么写这份文档（修订缘起）

《小学数学知识点盘点》把缺口直接列成「建议补全元认知」，于是 `seed.ts` 里元认知一口气扩到了 **MK-38**（新增 MK-29~MK-38 共 10 个）。

发起人指出核心问题：**其中不少是已有元认知的「直接拓展」，独立并不能解决问题。** 典型例子是 **运算定律（MK-38）**——它本就是加法 / 乘法的规律，早已在性质清单里（PP-01~PP-05 交换律 / 结合律 / 分配律）。硬提为元认知，既与性质重复，又破坏了「元认知 = 操作原子」这条最根本的判据。

本文目标有三条：

1. 用统一、可执行的判据，**重新逐项审定 MK-29~MK-38**，把不该当元认知的归位到「性质」或「策略」。
2. 补完一直空缺（建了表却没 seed）的 **性质系统** 和 **策略系统**，且**尽可能补全**。
3. 把「觉醒」确立为第二阶段核心机制，并用**知识守卫**作为本岛觉醒的练习载体，用**岛屿等级**承接觉醒后的内容升级。

一句话结论：**原本 38 个元认知回退为 29 个（28 + 因数倍数）；MK-29~MK-36 归「策略」；MK-38 归「性质」（并入 PP-01~PP-05）；性质体系补全到 30 个（其中 13 条为多精灵觉醒），覆盖 24/29 个元认知；每座岛的档位数 = 1 + 该岛可觉醒守卫数（从 1 档到 4 档不等）。**

## 1. 统一判定判据（收紧版）

| 类型 | 本质 | 判定红线（两条都满足才是它） | 游戏化 |
|------|------|------------------------------|--------|
| **元认知** | 操作原子（「会做什么」） | ① 能**独立**解一类题 ② 能作为父节点交叉出更新知识 | 精灵（收集 / 进化） |
| **性质** | 关于运算 / 图形的真理 | 不能独立解题；依附于元认知；只在「与策略组合」时生效 | 觉醒 / 镀金（精灵金纹逐条点亮） |
| **策略** | 串连元认知的思想方法 / 套路 | 用于攻克特定题型；本身**不产出新原子** | 连招（图鉴 / 隐藏挑战） |

> **「直接拓展」红线**：若某候选只能「用来形容 / 加速 / 重组已有的元认知去解题」，而**自身单独拿一道题出来就解不了**——它就不是元认知，应归性质或策略。

## 3. 运算定律专题（为什么是性质）

运算定律 = 加法 / 乘法运算中「换序、结合、分配」的规律。它描述「运算怎么动、结果不变」，是关于运算的**真理**，不是操作：

- 单独拿它解不了任何题（没有「输入数字、产出答案」的动作）。
- 必须作用在已有算式上，配合策略**简算（ST-01）**才生效（`25×(4+8)=25×4+25×8`）。
- 与《数学元认知图谱》PP-01~PP-05 完全重复 → **删除 MK-38 元认知身份，内容零丢失**。

游戏化归位：孩子在「简算 / 重组类」题里成功应用某定律 → 对应精灵**觉醒**该性质，图鉴镀金纹（不是新岛、不是新精灵）。

## 7. 游戏化机制：觉醒系统（核心）+ 连招 + 知识守卫

> 设计理念（发起人定案）：**孩子沿主线推进，旧知不断觉醒深化；卡在渡海 Boss 时也有成长退路。** 进化是纵向（新精灵），觉醒是横向（把老精灵镀厚）。

### 7.1 觉醒（性质 → 精灵镀金）

- 每条性质 = 含义 + 例题 + 伙伴讲解；觉醒后精灵图鉴多一道金纹。
- 觉醒顺序按教育顺序（先交换律 → 后结合律 → 再分配律），不跳序。
- 记录写入 `internalized_property(spirit_id, property_id, awakened_at, source)`，`source` 区分 `levelup / boss_prep / stuck`。

### 7.2 连招（策略 → 组合技法）

孩子用 ≥2 个元认知串起解题 → 记一次连招（`internalized_strategy`）；数学广角策略作为隐藏挑战出现。

### 7.3 数学广角归位后的地图变化

原 MK-29~36 的 8 座岛从主线 DAG 摘除，改为「隐藏挑战 → 连招」（击败点亮 ST-08~15，不产新精灵）。MK-37 保留为正常岛。

### 7.4 知识守卫（本岛觉醒的练习载体）★ 第二阶段核心落地

> **解决的概念错位**：进化 Boss 是「跨岛摆渡人」，而觉醒是「本岛的事」——本岛觉醒不该借 Boss 之名。知识守卫 = 本岛专属的「觉醒考验」，与渡海 Boss 语义分离。

**一座岛的三个角色：**

| 角色 | 管什么 | 前置 | 打赢得什么 |
|------|--------|------|-----------|
| 基础小怪 | 练基础题、攒熟练度 | 净化后就有 | 熟练经验 |
| **知识守卫 ✦（新增）** | **本岛觉醒的练习载体** | 该岛精灵已觉醒性质 | 岛屿升级 + 精灵镀金 |
| 渡海 Boss | 跨岛进化 | 掌握父元认知 | 新精灵（净化） |

**触发规则（发起人定案）：**

- **单精灵守卫（17 条性质）**：对应精灵达到等级门槛 → **本岛必定现身**，无随机。
- **多精灵守卫（13 条性质）**：相关精灵**均**达门槛（AND）→ 在相关岛屿中**随机现身** + 主界面广播「有些奇妙的事情发生了……」（相关岛亮金色感叹号）。
- **广播统一**：所有觉醒（含单精灵）都触发广播，文案区分「去哪找」：
  - 单精灵：「加法精灵似乎想起了什么……去加法岛看看它吧！」
  - 多精灵：「有些奇妙的事情发生了……乘法与加法的力量产生了共鸣！」
- **驻留规则**：守卫出现后驻留到被打败，不消失不刷新；广播只在首次达标时提示一次。
- **组合觉醒演出**：多精灵守卫 = 融合守卫（双色 / 双形象），打赢后相关精灵共同镀金。

**守卫升级链：** 觉醒第 1 条 → 守卫 I；觉醒第 2 条 → 守卫 II；觉醒第 3 条 → 守卫 III（外观金纹逐条变多）。

### 7.5 觉醒硬性前置链（不可跳过）

```
净化（打败渡海 Boss → 得新精灵）→ 练习（岛内打小怪 → 精灵等级提升）→ 觉醒（等级达标 → 守卫现身）→ 共同觉醒（多精灵均达标 → 融合守卫）
```

- **没有精灵就不可能升级，没升级就不可能觉醒**——觉醒永远排在「会做题」之后。
- 等级门槛按教育顺序：第 1 条性质 Lv2、第 2 条 Lv3、第 3 条 Lv4。

### 7.6 岛屿等级系统（守卫打赢 → 整岛升级）

- 新增 `island_level(island TEXT PK, level INTEGER DEFAULT 1)`；守卫打赢 → `level+1` → 解锁该档进阶小怪（性质题）。
- **档位数 = 1（基础）+ 该岛可觉醒守卫数**（不同岛档位数不同）：

| 档位 | 岛屿 | 数量 |
|------|------|------|
| 1 档（无性质） | 计数、负数、字母表示数、图形认识、位置方向、分类整理、统计图 | 7 |
| 2 档（1 条性质） | 位值、减法、除法、分数、小数、百分数、比、比例、方程、角、周长、体积、图形运动、单位换算、时间、可能性、集合 | 17 |
| 3 档（2 条性质） | 加法、因数倍数、面积 | 3 |
| 4 档（3 条性质） | 乘法、平均数 | 2 |

## 8. 题目体系设计（题目数量 × 精灵等级 × 觉醒档位）★ 代码核实后设计

### 8.1 现有题目真相（盘点）

题目**不是固定题库**，而是 `lib/questions.ts` 的**程序化出题器**：

- 29 个元认知各 1 个生成器（`GENERATORS`），内含 1~8 个故事模板 / 分支 + 随机数字 → 每次抽到不同数字和情境（「刷题不重样」，理论无限）。
- 另有 8 个「联手题」生成器（`COMBOS`：加法+计数、减法+加法、乘法+减法、位值+加法、除法+乘法、面积+乘法、平均数+加法、集合+分类整理）。
- 每场题目数：`4 + (level-1)`，封顶 7 招（`generateSteps`）；数字范围随 LEVEL 抬升（`dStep`）。
- 岛屿难度（现状）：`1 + 1×已开下游岛数 + 2×(精灵等级−1) + 手动偏置`（`getIslandDifficulty`）。
- 熟练度（现状）：每赢 1 场 `xp+1`，满 3 场 `mastery_level+1`（`trainWin`）。

### 8.2 设计：精灵等级 ↔ 觉醒时机 ↔ 题目数 ↔ 岛屿档位（统一映射表）

| 精灵等级 | 训练场次 | 觉醒时机 | 每场题目数 | 岛屿档位 | 解锁内容 |
|---------|---------|---------|-----------|---------|---------|
| Lv1 | 净化即 Lv1 | 无 | 4 招 | 1 档 | 基础小怪 |
| Lv2 | 再赢 3 场 | 觉醒第 1 条性质（守卫 I 现身） | 5 招 | 2 档 | 守卫 I + 第 1 条性质题 |
| Lv3 | 再赢 3 场 | 觉醒第 2 条性质（守卫 II） | 6 招 | 3 档 | 守卫 II + 第 2 条性质题 |
| Lv4 | 再赢 3 场 | 觉醒第 3 条性质（守卫 III） | 7 招 | 4 档 | 守卫 III + 第 3 条性质题 |

**规则：**

- **题目数量**：每场 = `4 + (精灵等级−1)`（封顶 7）——精灵练得越深，一场能打的越多。无性质岛固定 4 招。
- **题目难度**：数字范围 = `f(岛屿难度)`（沿用现有 `dStep`，含下游岛数 + 精灵等级 + 偏置）；**进阶性质题**在基础数字上再抬一档。
- **进阶题（性质题）**：岛档位 ≥2 后，进阶小怪出「用刚觉醒的性质解题」的题（凑整、简算、化简、容斥等）——每条性质 1 个生成器（第一批先做核心 6~8 条：交换律 / 结合律 / 分配律 / 减法连减 / 小数性质 / 比化简 / 容斥）。
- **题目个数口径**：不是「共有 N 道」，而是「生成器 × 随机组合」。现状 37 个生成器；第二阶段为 30 条性质补「性质题生成器」。

### 8.4 觉醒联手（觉醒后可以联手）★ 补充机制

> 用户提问「觉醒之后是否可以联手」——**可以，且必须补**。现有 `COMBOS` 只是「基础联手」（不用性质）；觉醒性质参与联手 = 新的「觉醒联手」层。

**三层题目结构：**

| 层 | 题目 | 前置 | 触发位置 |
|----|------|------|---------|
| 基础联手（现有 COMBOS 8 个） | 多精灵，不用性质 | 精灵已内化 | 训练中段穿插 |

**数据：** `SolveStep` 增加 `requires_properties?: string[]`（要求觉醒某性质），与 `requires`（多精灵）并存。示例：

```
{ type: "solve",
  prompt: "25×(4+8) 用分配律怎么算？",
  requires: ["MK-05","MK-03"],            // 多精灵
  requires_properties: ["PP-05"],          // 要求已觉醒分配律
  options: [...] }
```
