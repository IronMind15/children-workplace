## 2. 术语表（先定义，后使用）

| 术语 | 定义 |
|------|------|
| **孩子** | 使用产品的小学生（主用户） |
| **家长** | 查看伙伴日记的监护人（次用户） |
| **元认知** | 不可再分（或一般不再分）的"知识元/原子"。多个元认知可**组合**解决特定问题，或**组合**指向新元认知 |
| **交叉（组合）** | 元认知 × 元认知 的动作。有两种产出：① 解决特定问题；② 指向新元认知 |
| **进化** | 新元认知从旧元认知交叉诞生的**客观规律**（发生在知识图谱层） |
| **内化** | 孩子掌握一个新元认知 = 获得"使用对应精灵"的资格 / 一种标识（发生在探险家层） |
| **熟练度（熟练等级）** | 对某个元认知（精灵）的熟练程度，用等级（Lv1 起步）表示；打小怪训练胜利 → 熟练经验 +1，满阈值则等级 +1 |
| **外显** | 元认知以精灵形态呈现（每只精灵 = 一个元认知） |
| **精灵** | 元认知的具象载体，**一只精灵固定对应一个元认知**（如【加法】精灵）。**来源：净化岛屿 Boss** |
| **伙伴（引导者）** | 系统中的**唯一 AI 引导角色**：负责开场白、提示、鼓励、写伙伴日记、引导"发现新元认知"。是"陪伴感"的载体。区别于精灵（战斗单位，1:1 元认知）与探险家（孩子自己） |
| **小小探险家** | 孩子在知识世界的化身，具备三能力：**携带精灵队伍、内化知识、查看当前能力** |
| **怪物** | 代表一个"待解决问题"的对战单元 |
| **净化** | 打赢岛屿 Boss（渡海）→ 得到一只新精灵（= 一个新元认知），即元认知进化 |
| **性质** | 依附于元认知的规律（如交换律），非独立操作，不能独立解题 |
| **策略** | 串联元认知的组合技法（如简算、验算、画图） |
| **训练** | 岛内打"小怪"，用已有精灵组合解题、巩固掌握（不产生新精灵） |
| **主线** | 推荐的进化主干路径（计数 → 加减 → 乘除 → 分数 → 小数 → …） |
| **支线** | 从主线分叉出的可选路径（几何、统计等） |
| **渡海** | 从当前岛"进化"到下一岛的关卡（Boss） |
| **Boss（渡海怪）** | 岛屿之间的进化关卡，净化后产出新精灵 |
| **小怪** | 岛内的训练关卡，用于巩固组合与掌握 |
| **图鉴** | 已内化元认知（= 已拥有精灵）的集合 |
| **伙伴日记** | 面向家长的成长摘要（伙伴第一人称） |
| **大脑编辑器** | 调节**小小探险家**（玩家化身）自身风格 / 偏好 / 帮助力度的界面 |
| **知识迁移** | **产品愿景**：这套"元认知 → 进化 → 精灵"的学习方法，可迁移到其他学科（语文/英语…）乃至任意知识领域，未来演化成"各种知识都能这样学" |
| **合体进化** | 多个元认知（多父）通过进化算子交叉，进化出一个新元认知；表现为"多精灵合力净化一个 Boss"（原"知识迁移"的游戏机制） |

## 4. 核心机制（概念模型）

> 这是整个产品的灵魂，所有功能需求都从这一节推导而来。

### 4.1 双轴模型

| 轴 | 含义 | 数量 | 产出 |
|----|------|------|------|
| **组合轴** | 元认知按需排列，解决具体问题（应用题、混合运算） | **无限** | 解题 |
| **进化轴** | 少数组合"结晶"成新的元认知 | **有限（15 种）** | 新元认知 |

> 一句话：**组合是日常（无限），进化是组合的"结晶时刻"（有限）。**
> 一次战斗往往两轴同时发生：既用旧元认知解了题（组合），又点亮了新元认知（进化）。

### 4.2 三层成长（破解"进化"混淆）

| 层 | 对象 | 变化 | 关键词 | 谁决定 |
|----|------|------|--------|--------|
| 知识图谱层 | 元认知之间的关系 | 客观规律 | **进化** | 数学客观结构 |
| 探险家层 | 孩子的知识进度 | 主观进度 | **内化 / 升级** | 孩子的选择与进度 |
| 精灵层 | 元认知的具象载体（1 精灵 = 1 元认知） | 随净化进化 | **成长 / 进化** | 打 Boss 净化 |

> "净化怪物获得新元认知"（单次动作）与"知识体系升级"（累积状态）是**同一件事的动作与结果**，同属"探险家层"。

### 4.3 三种知识类型

| 类型 | 本质 | 判据（两条都满足才是元认知） | 数量(估) | 游戏化 |
|------|------|------------------------------|----------|--------|
| **元认知** | 操作原子（"会做什么"） | ① 能独立解题 ② 能交叉出新知识 | ~28 | 精灵（收集/进化） |
| **性质** | 规律（"关于操作的真理"） | 不能独立解题，依附于元认知 | 9 | 觉醒 / 镀金 |
| **策略** | 组合技法（"怎么串起来"） | 串联元认知的套路 | 7 | 连招 |

**性质挂靠示例**（性质通过 `belongs_to` 依附元认知）：

```
元认知「加法」 ──性质── 交换律、结合律
元认知「乘法」 ──性质── 交换律、结合律、分配律(同时引用加法)
```

### 4.4 进化算子（15 个 = 8 核心 + 7 领域）

> 完整清单与定义见《数学元认知图谱》§5。这里只列概要。

**核心算子（8 = 7 主 + 1 副，主司"数与运算"）：**

| # | 算子 | 机制 | 典型链 |
|---|------|------|--------|
| 1 | 反转 | 反过来操作 | 加法→减法、乘法→除法 |
| 2 | 聚合 | 重复操作打包 | 加法→乘法 |
| 3 | 等分 | 整体分成若干份 | 除法→分数 |
| 4 | 扩域 | 数域向外延展 | 整数→小数、正数→负数 |
| 5 | 升维 | 度量维度 +1 | 长度→面积→体积 |
| 6 | 抽象 | 符号替代具体数 | 运算→字母→方程 |
| 7 | 关系 | 表达两量比较关系 | 除法→比、分数→百分数 |
| 8 | 显现（副） | 交叉时显形出规律 | 乘法×加法→分配律 |

**领域算子（7，主司"几何/统计/量测"）：**

| # | 算子 | 机制 | 典型链 |
|---|------|------|--------|
| 9 | 分类 | 按属性分组 | 计数→分类整理 |
| 10 | 表征 | 数据→图形 | 分类整理→统计图 |
| 11 | 概率化 | 确定→随机 | 分类整理→可能性 |
| 12 | 重叠 | 分类时发现交集 | 分类整理→集合 |
| 13 | 细化 | 整体→局部特征 | 图形认识→角 |
| 14 | 变换 | 对图形施加操作 | 图形认识→图形运动 |
| 15 | 空间化 | 图形→空间定位 | 图形认识→位置方向 |

> 价值：进化算子 = 知识图谱"边"的类型 = AI 繁衍新怪的生成模板。
> MVP 只用「聚合」「反转」两个算子；其余 13 个是后续扩展的地基。

**图谱结构：有向无环图（DAG），允许多父交叉。**

> **边的语义（多路径约定）**：概念上进化允许多条路径；教育设计优先课本主流引入方式；MVP 只实现逻辑依赖（唯一父集合 = 主流路径），多路径作为后续"知识迁移"进阶玩法。详见《数学元认知图谱》§5。

> **合体进化（特色玩法）**：一个元认知可由多个父元认知交叉合成（如"平均数" = 加法 + 除法）。游戏表现为**多只精灵合力净化一个 Boss**。

### 4.5 地图结构（半线性主线 + 支线，方案 B）

```
                      ┌──→ 几何支线（图形认识→周长→面积→体积）
                      │
主线：计数 → 加法 → 乘法 → 除法 → 分数 → 小数 → …
        │       │
        └→ 减法 └→ 面积（需 长度 汇聚）
```

| 概念 | 游戏实现 |
|------|----------|
| 进化 | 相邻两岛之间的"渡海关卡"（Boss，打赢净化出新精灵） |
| 组合 | 当前岛内"普通关卡"（小怪，反复刷应用题/混合题） |
| 分叉 | 一个岛有多个"出海口"（加法岛可去减法岛，也可去乘法岛） |
| 汇聚 | 一个岛有多个"入口条件"（乘法岛需"加法+位值"已点亮） |

> 设计红利：孩子可**自选路线**，但每个出海口都标"前置元认知"，形成"引导而不死板"的探索。

### 4.6 精灵与内化模型（实体关系）

```
小小探险家（孩子化身，可调大脑编辑器 = 自己的风格/偏好）
   │ 携带
   └─ 精灵队伍（= 已内化元认知的集合）
        ├─ 【加法】精灵   ← 净化"加法岛 Boss"而来
        ├─ 【减法】精灵   ← 加法精灵渡海"反转"进化而来
        └─ 【乘法】精灵   ← 加法精灵渡海"聚合"进化而来
```

| 关系 | 规则 |
|------|------|
| 精灵 ↔ 元认知 | **1:1**：一只精灵 = 一个元认知 |
| 精灵来源 | **净化 Boss**：打赢渡海 Boss，得到一只新精灵（= 新元认知） |
| 内化 | **= 拥有并使用对应精灵的资格**，体现在精灵队伍里 |
| 队伍 | 探险家携带**多只**精灵，每只一个元认知，战斗时按需派对应精灵 |
| Boss vs 小怪 | **Boss = 净化（得新精灵）**；**小怪 = 训练（巩固组合与掌握）** |
| 大脑编辑器 | 作用于**探险家**（玩家化身），而非精灵 |

## 5. 产品范围（In / Out）

### 5.1 MVP 范围内（In）

- 小小探险家（携带精灵队伍、内化知识、查看能力）+ 大脑编辑器（调探险家化身）
- 数学主线：计数 → 加法 → 减法 / 乘法（一条清晰进化链，含 2~3 次渡海净化）
- 战斗系统（小怪训练：组合元认知解题）
- Boss 战（渡海净化：产出新精灵）
- 家长端（伙伴日记静态页）
- 全程点击交互，零自由文本输入

### 5.2 MVP 范围外（Out）

- 语音 ASR / TTS
- 真实聊天 UI
- 3D 场景
- 登录 / 多设备账号
- 多学科（MVP 仅数学，架构上预留迁移）
- 真实 AI 出题（MVP 用 mock，P1 接 DeepSeek）
- 数学广角隐藏挑战（P2，MVP 不做）

## 6. 核心流程状态机

> 书写约定：每个流程 = ① 状态机图（ASCII）+ ② 状态表 + ③ 转移表 + ④ 验收要点。
> 状态用 字母+数字 编号（T=训练、B=Boss 净化）。

### 6.0 战斗设计规范（游戏性与专业性的融合结论）

> 核心原则：**让"专业性动作"本身就是"游戏性动作"**，不做"做题 + 奖励动画"两张皮。

**三原则：**

| # | 原则 | 内容 | 落地点 |
|---|------|------|--------|
| 1 | 无血条/回合 | 训练题本质是"对/错"二元，不做血条 | 游戏性用"连击 + 星级"，专业性用"对错 + 提示重试"，零失败压力 |
| 2 | 拆招 = 多阶段 | "拆招"把问题拆成多个解题步骤，每步 = 应用一个元认知 | 简单题 1 步；应用题多步（串联元认知 = 组合轴落地） |
| 3 | 克制 = 对应题型 | 题型 ↔ 元认知一一对应 | 同名克制：加法题 → 加法精灵（选对 = 克制特效） |

**战斗一句话：** 识破题型 → 派克制精灵 → 多阶段拆招（连击）→ 星级结算，全程无血量惩罚，答错只提示重试。

---

### 6.1 小怪训练流程（识破 → 克制 → 多阶段拆招 → 星级结算）

> 小怪 = 岛内训练关，用已知元认知解题，巩固组合与掌握。**不产生新精灵。**
> 游戏性来源：克制特效 + 连击 + 星级；专业性来源：识破题型 + 应用元认知。**无血量惩罚。**

**状态机图：**

```
T0 岛内探索 ──点击小怪──→ T1 登场 ──开始──→ T2 识破题型 ──选对精灵──→ T3 多阶段拆招 ──完成──→ T4 星级结算 ──→ T0
                                                  │                        │
                                                  └──选错──→ T5 提示 ──→ T2   └──答错──→ T5 提示 ──→ T3(当前步)
```

**状态表：**

| 状态 | 名称 | 说明 |
|------|------|------|
| T0 | 岛内探索 | 当前岛屿地图，显示小怪与渡海 Boss |
| T1 | 登场 | 怪物亮相 + 报"招式"（问题）+ 伙伴开场白；可"开始战斗" |
| T2 | 识破题型 | 判断问题类型 → 从精灵队伍选对应元认知的精灵（= 选克制） |
| T3 | 多阶段拆招 | 把问题拆成 1~N 个解题步骤，每步应用一个元认知；每步答对连击 +1 |
| T4 | 星级结算 | 按"连击/失误次数"给 1~3 星 + 熟练经验 +1；可"继续探索" |
| T5 | 伙伴提示 | 选错精灵或答错时温柔提示，不判负 |

**转移表：**

| 从 | 事件 | 到 | 触发动作 |
|----|------|----|----------|
| T0 | 点击小怪 | T1 | 载入小怪问题数据 |
| T1 | 点击"开始战斗" | T2 | 展示精灵队伍 |
| T2 | 选中精灵 = 正确元认知 | T3 | 克制特效，进入拆招 |
| T2 | 选中精灵 ≠ 正确元认知 | T5 | 伙伴提示"效果不佳，换个精灵试试"，回到 T2 |
| T3 | 完成全部解题步骤 | T4 | 结算连击 + 星级 |
| T3 | 某步答错 | T5 | 伙伴提示该步，回到 T3 当前步重试 |
| T4 | 点击"继续探索" | T0 | 写成长记录（训练胜利 + 星级 + 熟练经验 +1） |

**验收要点：**

- 每只小怪必须带**正确元认知**（克制判定依据）+ **解题步骤列表**（拆招：1 步=简单题，多步=应用题）。
- 拆招步骤必须**纯点击**完成（点数字/点选项/拖拽），无文本输入。
- **零失败压力**：任何错误只进 T5 提示后重试，无血量、无"失败"终态。

### 6.2 渡海 Boss 净化流程（打赢 → 新精灵 = 新元认知）

> Boss = 岛屿之间的进化关，打赢后"发现新元认知 + 诞生新精灵 + 解锁新岛"。**与小怪训练的核心差异：包含"发现新元认知"环节（B3）。**

**状态机图：**

```
B0 渡海关口 ──点击Boss──→ B1 前置检查 ──满足──→ B2 观察Boss ──挑战──→ B3 发现新元认知
    ▲                         │                                              │点选正确
    │                         └──不满足──→ B6 伙伴提示 ──→ B0                ▼
    │                                                              B4 用新元认知解题 ──答对──→ B5 净化结算
    │                                                                    │                      │
    └──────────────────────────────────────────────────────────────      └──答错──→ B6 ──→ B4   └──→ 新岛
```

**状态表：**

| 状态 | 名称 | 说明 |
|------|------|------|
| B0 | 渡海关口 | 岛屿边缘的 Boss，标注进化方向（如"加法岛 → 减法岛"） |
| B1 | 前置检查 | 检查是否已内化前置元认知 |
| B2 | 观察 Boss | 显示 Boss + 新类型问题（旧元认知无法直接解，或解法"别扭"） |
| B3 | 发现新元认知 | 伙伴引导孩子"顿悟"新本领，点选新元认知的含义/名字 |
| B4 | 用新元认知解题 | 用新发现的本领解决 Boss 问题 |
| B5 | 净化结算 | 三件事一次性触发：内化元认知 + 诞生新精灵 + 解锁新岛（含进化演出） |
| B6 | 伙伴提示 | 温和引导（前置不足或答错），不判负 |

**转移表：**

| 从 | 事件 | 到 | 触发动作 |
|----|------|----|----------|
| B0 | 点击 Boss | B1 | 检查前置元认知 |
| B1 | 前置已满足 | B2 | 进入 Boss 战 |
| B1 | 前置未满足 | B6 | 提示"需要先掌握 XXX"，回岛 |
| B2 | 点击"挑战" | B3 | 开始"发现"环节 |
| B3 | 点选正确的新元认知含义 | B4 | 点亮新元认知概念 |
| B3 | 点选错误 | B6 | 温和提示，重选 |
| B4 | 答对 Boss 问题 | B5 | 内化 + 诞生精灵 + 解锁岛 |
| B4 | 答错 | B6 | 温和提示，回到 B4 |
| B6 | 点击"重试 / 回去" | B4 / B0 | 视情况 |

**验收要点：**

- B3（发现新元认知）是 Boss 战与小怪训练的**核心差异**，MVP 必须保留。
- B5 必须**原子性**触发三件事：内化元认知、诞生精灵、解锁岛屿（三者要么都发生，要么都不发生）。
- 进化方向由"进化算子"决定（如加法岛→减法岛 = 反转；加法岛→乘法岛 = 聚合）。

### 6.3 合体进化流程（多精灵合力净化，多父）

> 【待补充】多只精灵合力净化一个 Boss，交叉出新元认知（如加法 + 除法 → 平均数）。MVP 暂不实现，P1 补充。

### 6.4 探险家操作流（创建 / 地图 / 精灵队伍 / 能力）

> 探险家的日常操作闭环，串起 7.1~7.3 的功能。

**状态机图：**

```
E0 首次启动 ──创建完成──→ E1 主地图
E1 主地图 ──点击小怪──→ 小怪战斗(6.1) ──结束──→ E1
         ──点击Boss──→ Boss净化(6.2) ──结束──→ E1
         ──点击精灵队伍──→ E2 查看精灵 ──返回──→ E1
         ──点击图鉴──→ E3 查看能力(P1) ──返回──→ E1
```

**状态表：**

| 状态 | 名称 | 说明 |
|------|------|------|
| E0 | 创建探险家 | 首次进入，选名字 + 形象（纯点选，无键盘） |
| E1 | 主地图 | 显示当前岛屿的小怪与 Boss，及底部导航（精灵队伍/图鉴/成就） |
| E2 | 查看精灵 | 列出已内化元认知对应的精灵（1:1） |
| E3 | 查看能力 | 已内化元认知图鉴（P1，MVP 可省） |

**验收要点：**

- E0 必须纯点选完成，无文本输入。
- E1 是核心枢纽，战斗/Boss/精灵队伍都从这里进入。

## 7. 功能需求清单

> 书写约定：每条需求 = 用户故事（作为/我想要/以便）+ 验收标准（当…则…）+ 优先级 + 非目标。
> 优先级：**P0** = MVP 必须；**P1** = 重要可后；**P2** = 锦上添花。

### 7.1 探险家与大脑编辑器（P0）

**REQ-EXP-01 创建小小探险家（化身）**

- 作为：孩子
- 我想要：第一次进入时，点选名字和形象，创建我的"小小探险家"化身
- 以便：有一个代表"我"的角色去知识岛探险
- 验收标准：
  - 当 首次进入 App，则 进入创建流程（选名字 + 选形象）
  - 当 我点选一个名字和形象，则 完成创建，进入首页地图
  - 当 全程创建，则 无文本输入（名字为点选预设，非键盘输入）
- 非目标：不含自定义手绘形象、不含键盘输入名字

**REQ-EXP-02 大脑编辑器（调探险家化身）**

- 作为：孩子
- 我想要：用开关/滑块调整"我的风格"（帮助力度、鼓励风格）
- 以便：让伙伴对我的陪伴方式符合我的偏好
- 验收标准：
  - 当 我打开大脑编辑器，则 显示至少 2 个开关（如"多鼓励我""多给提示"）+ 1 个帮助力度滑块
  - 当 我调整开关，则 立即保存，并在后续伙伴台词中体现差异
  - 当 我调整帮助力度，则 伙伴提示的详略程度随之变化
- 非目标：不含调"精灵"性格（作用于探险家，不作用于精灵）

### 7.2 地图与导航（P0）

**REQ-MAP-01 岛内探索与渡海导航**

- 作为：孩子
- 我想要：在岛屿地图上看到小怪、渡海 Boss，并能自由点击进入
- 以便：自主选择去打怪还是去渡海进化
- 验收标准：
  - 当 我进入某岛屿，则 显示该岛的小怪列表 + 渡海 Boss（标注进化方向，如"加法岛 → 减法岛"）
  - 当 我点击小怪，则 进入小怪战斗（见 7.4）
  - 当 我点击 Boss 但前置元认知未满足，则 提示"需先掌握 XXX"，不可进入
  - 当 我点击 Boss 且前置满足，则 进入 Boss 净化（见 7.5）
- 非目标：不含 3D 场景、不含开放世界自由移动

### 7.3 精灵队伍（P0）

**REQ-SPI-01 查看精灵队伍（= 已内化元认知）**

- 作为：孩子
- 我想要：查看我拥有的精灵（每只 = 一个元认知）
- 以便：知道我掌握了哪些本领
- 验收标准：
  - 当 我打开精灵队伍，则 列出所有已内化元认知对应的精灵（形象 + 名称 + 元认知名）
  - 当 我尚未内化任何元认知，则 显示空状态（引导去渡海净化第一只 Boss）
  - 当 精灵数量与已内化元认知数量，则 严格一致（1:1）
- 非目标：不含精灵培养/喂食/属性加点

### 7.4 小怪训练战斗（P0）

**REQ-BATTLE-01 识破题型 + 派克制精灵**

- 作为：孩子
- 我想要：看到小怪的问题后，判断题型并派出对应元认知的精灵
- 以便：用正确的元认知去解题（专业动作 = 游戏动作）
- 验收标准：
  - 当 进入战斗，则 显示小怪形象 + 问题文字 + 伙伴开场白
  - 当 我选中"正确元认知"的精灵，则 显示克制特效，进入拆招
  - 当 我选中"错误元认知"的精灵，则 伙伴提示"效果不佳"，不判负，可重选
- 非目标：不含血量条、不含回合制

**REQ-BATTLE-02 多阶段拆招（含应用题多步）**

- 作为：孩子
- 我想要：把问题拆成一个个解题步骤，逐步点选完成
- 以便：一步步应用元认知（应用题 = 串联多个元认知）
- 验收标准：
  - 当 问题为简单题，则 只有 1 个拆招步骤
  - 当 问题为应用题，则 有多个拆招步骤（每个步骤对应一个元认知）
  - 当 每答对一步，则 连击数 +1，且该步可纯点击完成（点数字/点选项）
  - 当 某步答错，则 伙伴提示该步，回到该步重试（不判负）
- 非目标：不含文本输入、不含惩罚性扣分

**REQ-BATTLE-03 星级结算**

- 作为：孩子
- 我想要：完成战斗后看到 1~3 星评价和熟练度升级
- 以便：获得成就感，并激励我重复挑战
- 验收标准：
  - 当 完成全部拆招步骤，则 按"失误次数"结算 1~3 星
  - 当 结算完成，则 该元认知熟练经验 +1（满阈值则熟练等级 +1），写入成长记录
  - 当 我点"继续探索"，则 回到岛内地图
- 非目标：不含排行榜

### 7.5 Boss 净化（P0）

**REQ-BOSS-01 渡海净化流程（含"发现新元认知"）**

- 作为：孩子
- 我想要：打渡海 Boss，发现新元认知并净化它
- 以便：进化出新元认知、诞生新精灵、解锁新岛
- 验收标准：
  - 当 前置元认知已满足并点击 Boss，则 进入 Boss 战
  - 当 进入 Boss 战，则 必经"发现新元认知"环节（伙伴引导点选新元认知的含义，如"拿走=减法"）
  - 当 我点选正确的新元认知含义，则 点亮该元认知，进入解题
  - 当 我用新元认知答对 Boss 问题，则 触发净化结算
- 非目标：不含多精灵合力（那是 6.3 知识迁移，P1）

**REQ-BOSS-02 净化结算（原子性）**

- 作为：孩子
- 我想要：净化 Boss 后，一次性获得三样东西
- 以便：内化元认知 + 诞生精灵 + 解锁新岛，三者一致
- 验收标准：
  - 当 净化成功，则 同时发生：内化新元认知、精灵队伍新增对应精灵、解锁新岛
  - 当 净化结算，则 播放进化演出（精灵进化动画）
  - 当 三件事之一失败，则 全部回滚（事务原子性）
- 非目标：不含跨设备同步

### 7.6 能力与成长查看（P1）

**REQ-PANEL-01 内化图鉴（能力面板）**

- 作为：孩子
- 我想要：查看我已内化的元认知图谱（含进化连线）
- 以便：看清"我掌握了哪些知识、它们怎么进化而来"
- 验收标准：
  - 当 我打开图鉴，则 显示已内化元认知及其进化连线（父→子，标进化算子）
  - 当 元认知未内化，则 灰显/锁定，不显示连线
- 非目标：P1 实现，MVP 可简化为"精灵队伍"替代

**REQ-PANEL-02 成长记录**

- 作为：孩子
- 我想要：查看我的成长记录（打怪、进化、里程碑）
- 以便：看见自己的进步轨迹
- 验收标准：
  - 当 我打开成长记录，则 按时间列出事件（训练胜利、净化、进化）
- 非目标：P1 实现

### 7.7 家长端（P0）

**REQ-PARENT-01 伙伴日记（温柔共育）**

- 作为：家长
- 我想要：通过"伙伴日记"了解孩子成长（无分数排名）
- 以便：温柔地参与共育，而非监控
- 验收标准：
  - 当 我从隐藏入口（长按设置）进入，则 看到伙伴第一人称写的成长摘要
  - 当 查看日记，则 不含分数、排名，只有学习/情绪关键词
- 非目标：P1 实现；不含实时监控、不含推送

### 7.8 隐藏挑战（P2）

**REQ-HIDDEN-01 数学广角隐藏怪**

- 作为：孩子
- 我想要：在岛屿中发现隐藏怪（数学广角：推理、优化等）
- 以便：获得额外的挑战与丰厚奖励
- 验收标准：
  - 当 满足触发条件（如内化到某元认知），则 隐藏怪出现
  - 当 击败隐藏怪，则 获得比普通小怪更丰厚的奖励
- 非目标：P2 实现，MVP 不做

## 8. 数据需求

> 数据分三层：知识结构（静态预置）、游戏实体（动态）、进度（动态）。
> 数据库：node:sqlite（SQLite），MVP 单机单设备，无登录。

### 8.1 数据分层总览

| 层 | 表 | 静态/动态 | MVP |
|----|----|-----------|-----|
| 知识结构 | meta_cognition、evolution_edge、property、strategy | 静态（预置） | 前两个必须 |
| 游戏实体 | monster、spirit | 静态+动态 | monster 必须 |
| 进度 | explorer、internalized_meta、growth_log | 动态 | 全部必须 |

### 8.2 知识结构（静态，来自《数学元认知图谱》）

**meta_cognition（元认知，28 个）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT PK | 如 `MK-03` |
| name | TEXT | 名称（加法） |
| meaning | TEXT | 核心意义 |
| domain | TEXT | 领域（数与运算/图形几何/…） |
| is_mvp | INTEGER | 是否 MVP（0/1） |

**evolution_edge（进化边，多父 + 多路径）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT PK | 边 ID |
| from_meta | TEXT | 父元认知 id |
| to_meta | TEXT | 子元认知 id |
| operator | TEXT | 进化算子（反转/聚合/…） |
| is_primary | INTEGER | 是否主流路径（MVP 只走 is_primary=1） |

> 多父 = 多条边指向同一 `to_meta`。多路径 = 同一 `to_meta` 有多组边，MVP 只启用 is_primary 那组。

**property（性质，9 个）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT PK | 如 `PP-01` |
| name | TEXT | 名称（加法交换律） |
| belongs_to | TEXT | 依附的元认知 id（多值用 JSON 数组，如分配律 `["MK-05","MK-03"]`） |

**strategy（策略，7 个）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT PK | 如 `ST-01` |
| name | TEXT | 名称 |
| effect | TEXT | 作用 |

### 8.3 游戏实体

**monster（怪物：Boss / 小怪 / 隐藏）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT PK | |
| name | TEXT | 怪物名 |
| type | TEXT | `minion` 小怪 / `boss` 渡海 / `hidden` 数学广角隐藏怪 |
| island | TEXT | 所属岛屿 |
| question | TEXT | 问题文字 |
| correct_meta | TEXT | 正确元认知 id（小怪：选精灵判定依据） |
| target_meta | TEXT | 目标新元认知 id（Boss：净化后产出） |
| prerequisites | TEXT | 前置元认知 id 列表（JSON 数组，Boss 用） |
| options | TEXT | 选项（JSON，含正确答案标记） |
| steps | TEXT | 解题步骤列表（JSON：拆招步骤，简单题 1 步，应用题多步） |

**spirit（精灵，1:1 元认知）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT PK | |
| meta_id | TEXT | 对应元认知 id（1:1） |
| emoji | TEXT | 形象 |
| nickname | TEXT | 精灵名（可由孩子命名） |

### 8.4 进度数据

**explorer（小小探险家）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT PK | 单设备默认 `default` |
| name | TEXT | 化身名 |
| brain_settings | TEXT | 大脑编辑器（JSON：帮助力度/鼓励风格） |
| current_island | TEXT | 当前岛屿 |

**internalized_meta（内化记录 = 已拥有精灵）**

| 字段 | 类型 | 说明 |
|------|------|------|
| meta_id | TEXT | 已内化的元认知 id |
| acquired_at | TEXT | 获得时间 |
| source | TEXT | 来源（boss / hidden） |
| mastery_level | INTEGER | 熟练等级（Lv1 起步，默认 1） |
| mastery_xp | INTEGER | 熟练经验（满阈值则等级 +1） |

**growth_log（成长记录）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK AUTOINCREMENT | |
| event | TEXT | 事件类型（train_win / purify / levelup …） |
| detail | TEXT | 详情 JSON |
| created_at | TEXT | 时间 |

### 8.5 关系一句话

- 精灵 1:1 元认知（`spirit.meta_id` ↔ `meta_cognition.id`）
- 内化 = `internalized_meta` 里有一条 `meta_id` 记录（= 拥有对应精灵）
- 净化 Boss = 写一条 `internalized_meta` + 解锁岛（`explorer.current_island`）
- 进化 = `evolution_edge` 里的一条边（`from_meta` → `to_meta`，带 `operator`）

## 9. 非功能需求

> 非功能需求 = 不针对某个功能，而是全局的质量约束。每条也带"验收标准"。

### 9.1 儿童内容安全（P0，硬约束）

- 约束：所有展示内容（含 AI 生成）必须健康、积极、适合 1~6 年级。
- 验收标准：
  - 当 内容涉及暴力/隐私/危险行为，则 系统必须谨慎引导或拒绝输出
  - 当 伙伴台词由 AI 生成，则 系统提示词中必须含"内容健康积极"约束（见 deepseek SYSTEM_PROMPT 规则）

### 9.2 防沉迷与时间管理（P1）

- 约束：保护孩子用眼与作息。
- 验收标准：
  - 当 单次连续使用超过设定时长，则 伙伴提示"我要休息啦，明早再来找我吧"
  - 当 家长在设置里调整时长，则 生效

### 9.3 隐私与数据（P0）

- 约束：儿童数据不出本地（MVP）。
- 验收标准：
  - 当 MVP 阶段，则 数据仅存本地 SQLite，不联网上传
  - 当 MVP 阶段，则 无账号、无第三方追踪

### 9.4 性能（P0）

- 约束：流畅、可点击。
- 验收标准：
  - 当 页面/动画加载，则 常规移动设备上无卡顿（动画 60fps 目标）
  - 当 进入战斗，则 首屏渲染 ≤ 2 秒

### 9.5 移动端适配（P0）

- 约束：手机/平板优先，桌面可用。
- 验收标准：
  - 当 在手机竖屏打开，则 布局正常（沿用 max-w-md 单列）
  - 当 点击按钮，则 触控目标 ≥ 44px，误触少

### 9.6 儿童友好交互（P0）

- 约束：大、圆、少、图>字、有反馈、有陪伴感。
- 验收标准：
  - 当 任意核心操作，则 均可纯点击/拖拽完成，无文本输入
  - 当 孩子操作，则 有即时视觉/音效反馈
