> 状态：当前 islands 节点在群岛主视图坐标全错（来自旧的 `getWorldLayout` 按 DAG depth 自动派生）。
> 本文档说明 **当前识别逻辑** 与 **人工调整方法**，待视觉对照设计稿后填精校坐标。

## 一、当前识别逻辑

### 数据流（app/page.tsx → components/WorldMap.tsx）

1. `app/page.tsx` 服务端拉数据：
   ```ts
   const layout = getWorldLayout();           // lib/worldLayout.ts → lib/repo.ts
   const worldNodes = allMetas.map((m) => {
     const c = layout[m.id];
     return { metaId: m.id, island: `${m.name}岛`, x: c?.x ?? 50, y: c?.y ?? 50, depth: c?.depth ?? 0, page: pageOf(m.id), ... };
   });
   ```
2. `WorldMap` 接收 `nodes: WorldNode[]`，按 `safePage` 切页：
   ```ts
   const currentPageNodes = nodes.filter((n) => n.page === safePage + 1);
   ```
3. 渲染时用百分比坐标：
   ```tsx
   <button style={{ left: `${n.x}%`, top: `${n.y}%` }}>...</button>
   ```

### 坐标来源（lib/worldLayout.ts `getWorldLayout()`）

- 算法：按进化谱系 DAG 计算每个 MK 的 `depth`（根=0，子=max(parents.depth)+1）
- 同 depth 横向均分（8% → 92%），depth 越大 y 越靠上（86% → 12%）
- **问题**：7 群岛主题切分后，按 depth 排的坐标与设计稿无关
  - 例：`MK-07 分数`（depth=2）现在被分到群岛 4，但默认坐标仍在"全局第 2 层"位置，与群岛 4 的设计稿对不上
- 整个 `getWorldLayout()` 是基于全岛 29 个 MK 的全局 DAG，与"7 张群岛背景图各自的局部坐标"是两套坐标系

### 渲染层（components/WorldMap.tsx）

```tsx
<div className="relative h-[60vh] min-h-[480px] w-full overflow-hidden rounded-xl bg-cover bg-center"
     style={{ backgroundImage: `url(${getArchipelagoBg(safePage + 1)})` }}>
  {currentPageNodes.map((n) => (
    <button key={n.metaId} style={{ left: `${n.x}%`, top: `${n.y}%` }} ...>
      {/* 小圆圈 + 中央点 + 亮光 + 岛屿名 */}
    </button>
  ))}
</div>
```

## 二、人工调整方法

### 方案 A：精校坐标（推荐）

新增 **`lib/islandCoords.ts`**（纯数据层，无 DB 依赖，client 可安全 import）：

```ts
// 岛屿名 → 群岛局部坐标（百分比，0~100 对应群岛背景图的宽高）
// 由视觉对照设计稿逐岛量测后填入；未填的岛回退到 getWorldLayout 的旧坐标。
export const ISLAND_COORDS: Record<string, { x: number; y: number }> = {
  // === 群岛 1：数与运算基础（背景图 public/archipelagos/arch_01.webp）===
  "计数岛":    { x: 18, y: 72 },
  "位值岛":    { x: 32, y: 60 },
  "加法岛":    { x: 50, y: 50 },
  "减法岛":    { x: 68, y: 60 },
  "乘法岛":    { x: 82, y: 72 },
  // === 群岛 2：数的扩充（arch_02.webp）===
  "除法岛":    { x: 22, y: 65 },
  "小数岛":    { x: 40, y: 50 },
  "百分数岛":  { x: 58, y: 50 },
  "负数岛":    { x: 70, y: 65 },
  "因数倍数岛":{ x: 50, y: 80 },
  // === 群岛 3：平面图形（arch_03.webp）===
  "图形认识岛":{ x: 20, y: 70 },
  "角岛":      { x: 45, y: 45 },
  "周长岛":    { x: 65, y: 55 },
  "面积岛":    { x: 80, y: 75 },
  // === 群岛 4：立体变换（arch_04.webp）===
  "体积岛":    { x: 25, y: 70 },
  "图形运动岛":{ x: 45, y: 50 },
  "位置方向岛":{ x: 65, y: 60 },
  "分数岛":    { x: 80, y: 75 }, // ★ MK-07
  // === 群岛 5：统计概率（arch_05.webp）===
  "分类整理岛":{ x: 20, y: 65 },
  "统计图岛":  { x: 42, y: 50 },
  "平均数岛":  { x: 62, y: 50 },
  "可能性岛":  { x: 80, y: 70 },
  // === 群岛 6：关系代数（arch_06.webp）===
  "比岛":      { x: 22, y: 60 },
  "比例岛":    { x: 42, y: 45 },
  "字母表示数岛": { x: 60, y: 50 },
  "方程岛":    { x: 78, y: 70 },
  // === 群岛 7：量测广角（arch_07.webp）===
  "单位换算岛":{ x: 25, y: 65 },
  "时间岛":    { x: 50, y: 50 },
  "集合岛":    { x: 75, y: 70 },
};

/** 取岛坐标（优先精校表，未填回退到全局 DAG 算法） */
export function getIslandCoord(metaId: string, fallback?: { x: number; y: number }): { x: number; y: number } {
  // 由调用方提供 fallback（getWorldLayout 算出的全局坐标）
  return ISLAND_COORDS[metaId] ?? fallback ?? { x: 50, y: 50 };
}
```

> 注：上面坐标只是**示意占位**，需要用图像编辑器（Photoshop/Figma/Python+PIL）量测每张群岛背景图的实际岛屿位置后再填。

### 接入步骤

1. **量测**：用图像编辑器打开 `public/archipelagos/arch_01~07.webp`（分辨率 1216×706 或 1586×992），找到每座岛的位置中心，记下 `x%, y%`
2. **填表**：把量测结果写到 `lib/islandCoords.ts` 的 `ISLAND_COORDS`
3. **接入**：`app/page.tsx` 把 `getWorldLayout()` 的坐标作为 fallback，传给 `getIslandCoord(metaId, fallback)`：
   ```ts
   const layout = getWorldLayout();
   const worldNodes = allMetas.map((m) => {
     const c = layout[m.id];
     const coord = getIslandCoord(m.id, c);
     return { metaId: m.id, ..., x: coord.x, y: coord.y, ... };
   });
   ```
4. **验证**：浏览器访问 http://localhost:3000，逐页切群岛看节点是否落在对应岛的位置

### 方案 B：设计稿驱动的全量重标定（如果旧坐标完全不能复用）

如果 `getWorldLayout()` 的旧坐标与新群岛背景图完全错位（不只是局部偏差），可直接：
1. 在 `ISLAND_COORDS` 里填**全部 29 座岛的精确坐标**
2. 简化 `getWorldLayout()`：不再算 depth 坐标，仅返回 depth 字段供 WorldAtlas 用
3. `app/page.tsx` 用 `getIslandCoord()` 直接拿坐标，不需要 fallback
