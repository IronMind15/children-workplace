## 二、设计稿主色调提取（Python 量化分析）

对 35 张页面稿取色，得出设计稿的统一色板：

| 角色 | 色值 | 出现频率 | 用途 |
|------|------|----------|------|
| **主背景** | `#fdfceb` ~ `#fefdf2` | 所有页面稿主色 | 米黄/奶油温暖底色 |
| **主强调色** | `#f79228` / `#f6962c` / `#f98728` | 6/7/8/9/2-5/3-3/3-5/4-1 | 橙色（按钮 / 标题 / 主角色） |

| **草地块** | `#d4e790` / `#d1e48b` | 7 | 黄绿（柔和草地，非纯绿） |
| **暗部** | `#14161b` / `#1a1d22` | 3-4 | 近黑（少量文字 / 强对比区） |

- 暖色为主，米黄打底，橙色做主强调

- 对比柔和，适合儿童长时间观看
- 几乎没有纯黑纯白，最暗也只到 `#14161b`

## 三、当前项目代码的视觉风格

### 3.1 色彩系统（`app/globals.css`）

| 角色 | 当前色值 | 设计稿目标 |
|------|----------|------------|
| 主色 | `--color-primary: #2e7dd1`（海洋蓝） | `#f79228`（橙） |
| 背景 | `.sky-bg: linear-gradient(#b8e2ff → #eef6fc)` 蓝天 | `#fdfceb` 米黄 |
| 面板 | `.pixel-panel: 白底 + 4px #2b3a4a 黑边 + 硬阴影` | 米黄底 + 细边圆润 |
| 暗面板 | `.pixel-panel-dark: #22303f 深蓝灰` | 几乎不用深色底 |
| 按钮 | `.pixel-btn: 4px 黑边 + 5px 硬阴影 + 下沉感` | 圆角橙色实心 |
| 草地 | `.grass-checker: #9adb5c/#8fd14f 棋盘格` | `#d4e790` 柔和黄绿 |
| 海面 | `repeating-linear-gradient 蓝条纹` | `#96e3eb` 纯青 |

**冲突点**：整套 `pixel-*` 类是 8-bit 游戏机风，设计稿是童书插画风，**两者色相、明度、描边语言完全不同**。

### 3.2 精灵/怪物渲染（`lib/sprites.ts` + `PixelSprite.tsx`）

- 当前用 **16×16 字符画** 渲染成 SVG（`shapeRendering="crispEdges"` 锐利像素边）
- 4 个模板（SLIME/APPLE/BOSSBEAST/SPIRIT）× 换色 = 全部 28 岛 + 怪物
- 风格参考：保卫萝卜 / 宝可梦

**设计稿方向**：6 张 `A_cute_chubby_*` + 6 张 `A_massive_imposing_*` 是 AI 生成的卡通插画怪物图，**与字符画像素风完全不是一个体系**。

### 3.3 字体

- 当前：`PingFang SC / Microsoft YaHei` + `font-black`（900 字重）大量使用
- 设计稿：圆润手写感，字重偏中（推测 500-600）

## 五、改造方案（三选一）

### 方案 A：激进全换（推荐 ⭐）

**思路**：彻底切到设计稿风格，像素风作为「怀旧皮肤」保留切换开关（可选）。

**执行步骤**：
1. **确认设计稿映射**（你 + 设计师）：逐张标注 35 张页面稿对应哪个路由/状态
2. **重写色板**（`globals.css` `@theme`）：按设计稿提取的 6 色重写
3. **重写基础组件类**：`pixel-panel` → `card`（米黄底细边圆角）、`pixel-btn` → `btn`（橙色实心圆角）
4. **替换精灵/怪物体系**：`PixelSprite` 字符画 → 图片资源渲染组件（`<img>` 或 SVG）；`sprites.ts` 改为资源路径映射表
5. **逐页面重写视觉层**：按设计稿 1:1 还原，保留数据/逻辑层不动
6. **次要路由决策**：砍 `/brain /parent`（自测用），保留 `/spirits /growth /journal` 但用新风格

**优点**：一步到位，视觉统一
**缺点**：工作量大（预计改 18 个组件 + globals.css + sprites.ts）；精灵/怪物需设计稿出齐全部资源
**风险**：设计稿怪物只有 12 张，28 岛全量怪物 + 精灵 + Boss 资源可能不够，需补充生成

### 方案 B：渐进迁移（保守）

**思路**：先改色彩 + 面板 + 字体（视觉骨架），精灵/怪物暂时保留像素风，后续资源齐了再换。

**执行步骤**：
1. 同方案 A 第 1-3 步
2. `PixelSprite` 加一层 wrapper：未来可一键切「像素」/「插画」两种渲染
3. 只重写首页 + 战斗页 + Boss 页 3 个核心页面的视觉
4. 次要页保持现状，后续再改

**优点**：风险低，见效快，不阻塞在资源不全上
**缺点**：过渡期风格割裂（像素怪物 + 米黄面板）

### 方案 C：双主题并行

**思路**：设计稿风格作为新主题，旧像素风保留，用户可切换。

**优点**：不破坏现有体验
**缺点**：维护两套样式成本高，不推荐（除非要做「怀旧模式」彩蛋）
